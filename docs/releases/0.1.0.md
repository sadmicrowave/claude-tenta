# Claude Tenta 0.1.0

The first release. Claude Tenta offloads slow, repeatable jobs from your laptop to a spare Linux machine on your own network, using two private GitHub repositories as the mailbox. There is no open port and no server to expose: your computer pushes a job file, the worker pulls it, runs it in a jail and pushes the result back.

## What you get

- **One wizard, two computers.** `ct-setup install` asks its questions once, sets up your computer and the worker over SSH, adds the deploy keys to GitHub for you and runs a first job to prove the whole loop works.
- **Jobs that cannot reach your secrets.** Every job runs in a bubblewrap jail with no network, no capabilities and no view of the worker's home or configuration. Output is scanned before it leaves the machine, decoy credential files trip a lockdown, and the worker locks itself when something looks wrong.
- **Approvals you sign yourself.** A job that needs your OK is approved from your own computer with a key only you hold. The signature covers the exact job file, so what you read is what runs. No login to the worker is needed.
- **Root-level actions, without handing a job `sudo`.** A command that must run as root is registered as a pinned, typed action (`ct-admin action add`), approved per job with your signature, and run by a small root helper in its own sandbox. It refuses to run where the sandbox cannot be enforced.
- **A registry you control.** What the worker may run is a signed list of job classes. `ct-admin adopt` turns a command you have tested into a class; `ct-admin retire` and `ct-admin action remove` take one away.
- **Several workers, compared.** `ct-admin workers` lists every worker you run side by side: hardware, Claude access and state, release, load and heat.
- **Quiet when idle.** The worker checks GitHub every few seconds while busy, less often when idle and least often when asleep (all configurable).
- **Updates you decide on.** A silent banner says when a newer release exists; `ct-admin update` shows what changed and installs it on your computer and the worker if you agree.
- **A consistent, themeable look.** Every screen is a card; the colours are roles in one theme you can change with a single file (`ct-admin theme`).

## Requirements

- A worker running Ubuntu or Debian (tested on Ubuntu 24.04 and 26.04) that you can SSH into with a key, and a computer to run the commands from (macOS or Linux).
- `git`, `ssh` and (for the automatic key setup) the GitHub `gh` command on your computer.
- Claude Code on the worker is optional; every other job class runs without it.
- A terminal with colour is recommended; piped output is plain text.

## Known limits

- The tripwire (decoy credential files) needs kernel audit; machines without it (containers) report that check as skipped.
- Root-level actions need a systemd that really enforces its sandbox; the worker tells you if it does not.
- One worker per install today; the comparison command is the first step towards scheduling across several.
- The jail shares the kernel: it is a namespace sandbox, not a virtual machine.

## Moving from a pre-release install

An install made before the project was renamed (named `claude-ballast`, commands `cw-*`) is moved with one command: `ct-setup rename claude-tenta` (preview first, then `--apply`). Job history, secrets and keys are kept.
